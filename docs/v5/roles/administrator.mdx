# Administrator Guide

Administrators work at two scopes. **System Admin** is a platform-wide system
role; **Organization Admin** is scoped to one organization. A user may hold
both. See [Role Model](/roles/role-model) for how system and organization roles
combine.

## Administrator roles

| Role | Scope | What it grants |
| --- | --- | --- |
| System Admin | System | Highest system administrator; all functional permissions across organizations |
| Organization Admin | Organization | Console, Audits, and Workbench within one organization |

## System Admin

System Admin can use every module and every organization. The role is intended
for platform operators who configure the deployment, manage organizations and
roles, and handle cross-organization access and audit requirements.

- [General](/features/general/) — organization switching, search, profile, and dashboards
- [Console](/features/console/) — users, groups, assets, accounts, authorizations, ACLs, and tags
- [PAM](/features/pam/) — account automation, security, integrations, and activity
- [Audits](/features/audits/) — sessions, activities, job and ticket audits, and reports
- [Workbench](/features/workbench/) — job center, tickets, and tools
- [System Settings](/features/system-settings/) — organizations, roles, authentication, storage, components, and license
- [Client](/features/client/) — Luna, desktop client, connectors, and troubleshooting

## Organization Admin

Organization Admin is scoped to a single organization. It can administer that
organization's identity, assets, access policy, and audit views, but it does not
change platform-wide settings or other organizations.

## Scope boundaries

- **System Settings**, **PAM lifecycle automation**, and **cross-organization
  audits** are platform-level concerns. Use System Admin (or a custom role with
  the required permissions).
- Organization Admin sees only the active organization. Switch organizations
  before managing records that belong to another organization.
- Built-in roles cannot be edited or deleted. Create or clone a custom
  organization role when the default permissions do not fit.

## Assigning administrator roles

1. Assign **System Admin** on the user's system roles for platform-wide administration.
2. Invite the user to an organization with **Organization Admin** for organization-scoped administration.
3. Review the role combination in [Role Model](/roles/role-model) before granting both.
