# Operator Guide

Operator access is built from two layers: a **System Operator** system role and
an **Organization Operator** organization role. The organization role is what
grants day-to-day Workbench access inside a specific organization. See
[Role Model](/roles/role-model) for the general model.

## Operator roles

| Role | Scope | What it grants |
| --- | --- | --- |
| System Operator | System | General baseline role; intended to be combined with an organization role |
| Organization Operator | Organization | Workbench within one organization |

<Alert type="note">
System Operator alone is not a complete operations role. Assign
**Organization Operator** in the organization where the user needs to connect to
assets and perform day-to-day work.
</Alert>

## Scope boundaries

- Console administration, PAM lifecycle automation, Audits, and System Settings
  are not part of Organization Operator by default.
- **Flow Setup** in Workbench > Tickets & Approvals is an administrative
  configuration, not an operator task. Operators use **Submitted** and
  **Assigned**.
- To use Workbench in another organization, assign Organization Operator there
  and switch organizations.

## Assigning operator roles

1. Assign **System Operator** as the user's system role when a baseline account
   is required.
2. Invite the user to the target organization with **Organization Operator**.
3. Switch organizations to confirm the Workbench shows the expected authorized
   assets.
