# Audits Dashboard

The **Audits Dashboard** is the landing page of the Audits workspace. It summarizes authentication, session, command, file-transfer, and job activity for the organization selected in the top navigation bar, so auditors and administrators can spot unusual volume or failed activity before opening the record-level pages.

## Open the dashboard

<Steps>
<div>
Switch the workspace to **Audits** from the workspace switcher in the top navigation bar.
</div>
<div>
Select **Dashboard** in the left sidebar.
</div>
<div>
Choose **Today**, **Last 7 days**, or **Last 30 days** at the top of the page. The selection is remembered in the current browser.
</div>
</Steps>

![Figure 1: Audits Dashboard with log and session counters, login and command charts, session trends, job execution totals, and connection trends.](/images/jumpserver/v5_session_audit_dashboard.png)

## Counters

The top cards summarize the selected time range.

| Card | Metric | Description |
| --- | --- | --- |
| Log data | Total login logs | Sign-in records, including both successful and failed attempts. |
| Log data | Operation logs | Changes to platform resources recorded by the operation log. |
| Log data | Password change logs | Password changes for JumpServer platform users. |
| Session data | Online sessions | Sessions that are currently connected. |
| Session data | Total historical sessions | Sessions that ended during the selected range. |
| Session data | Number of file transfers | Files uploaded to or downloaded from assets through JumpServer. |
| Job executions | Total job executions | Job runs started during the selected range. |
| Job executions | Running jobs | Job runs that are still executing. |
| Job executions | Failed execution actions | Job runs that completed with failures. |

## Charts

- **Login logs** compares successful and failed sign-ins as a donut chart and shows the total number of login records. Use [Login Logs](/features/audits/activities/login-logs) when you need to see the reason for a failure.
- **Commands** compares dangerous commands with other recorded commands and shows the total number of command records. Open [Session Commands](/features/audits/sessions/session-commands) to inspect the command text and output.
- **Session trends** plots the number of sessions per day as a line chart.
- **Session connection trends** plots daily connections as a column chart.

If a chart has no data in the selected range, it still shows its axes and legend but no series. This usually means that there is nothing to display rather than a rendering problem.

## Drill down

The counters are summaries only. Use the matching list page when you need individual records:

- [Asset Sessions](/features/audits/sessions/asset-sessions) and [File Transfer](/features/audits/sessions/file-transfer)
- [Login Logs](/features/audits/activities/login-logs), [Password Change Logs](/features/audits/activities/password-change-logs), and [Operate Logs](/features/audits/activities/operate-logs)
- [Job Executions](/features/audits/jobs/job-executions)
- [User Reports](/features/audits/reports/user-reports), [Asset Reports](/features/audits/reports/asset-reports), and [Account Reports](/features/audits/reports/account-reports)

## Notes

<Alert type="note">
The dashboard shows data from the organization selected in the top navigation bar, and each metric requires the matching audit permission. If a card is missing or empty even though activity exists, check the organization selection and your role permissions.
</Alert>
