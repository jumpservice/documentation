# Adhoc

**Adhoc** runs a command once against one or more authorized assets. It is the
fast path for day-to-day operations: select the targets, enter the run user and
the command, execute, and read the result per asset without logging in to each
machine. Nothing is saved unless you choose to save the command as a template.

![Figure 1: Adhoc page with selected assets, run user, module, and command editor.](/images/v5/jumpserver/v5_admin_wb_adhoc_01.png)

## Prerequisites

- The **Job Center** feature is enabled by an administrator in
  [Feature Settings](/features/system-settings/general/features). When it is disabled, the
  Job Center entries are hidden.
- Your role grants the permissions required to view and execute jobs.
- Your account is authorized for the target assets, including the account you
  intend to run as.

## Execute a command

<Steps>

<div>
  In **Selected assets**, click **Click to add** and choose one or more
  authorized assets or nodes. The selected targets appear in the list.
</div>

<div>
  Enter the **Run user**, for example `root`. Autocomplete suggests usernames
  that exist on the selected assets.
</div>

<div>
  Choose an **Account policy** for assets where the run user does not exist.
</div>

<div>
  Choose the **Module** that matches the command: Shell, PowerShell, Raw,
  Python, a database module, or CloudEngine.
</div>

<div>
  Type the command in the editor. Optionally set a timeout and a running path,
  then click **Execute**.
</div>

<div>
  If some assets cannot run the command, review the runnable and unrunnable
  lists and confirm the remaining targets. Output streams into the terminal
  below.
</div>

</Steps>

![Figure 2: Adhoc execution output for the selected assets.](/images/v5/jumpserver/job_adhoc_exec.png)

## Field reference

| Field           | Description                                                                                                |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| Selected assets | Authorized assets or nodes that receive the command                                                        |
| Run user        | Login account used on the targets                                                                          |
| Account policy  | What to do when the run user is missing: **Skip this asset**, **Privileged first**, or **Privileged only** |
| Module          | Interpreter for the command: Shell, PowerShell, Raw, Python, CloudEngine, or a database module             |
| Command         | The command text executed on every selected asset                                                          |
| Timeout         | Optional time limit; `-1` means no timeout                                                                 |
| Running path    | Optional working directory; otherwise the user's home directory is used                                    |
| Output          | Combined per-asset output, with refresh and download actions                                               |

<VersionBadge version="5.2.0" /> The database module also runs against DB2,
ClickHouse, Dameng, OceanBase, and Oracle. Select the matching database module
and confirm that the target accounts can run the command.

The toolbar also provides **Open command** to load a saved script template,
**Save command** to store the current command as a template, and a help entry for
template variables. Commands loaded from a template prompt for any variables
before running.

## Notes

<Alert type="warning">
  The command executes immediately on every selected asset. Check the command
  text and the target list before clicking **Execute**.
</Alert>

<Alert type="note">
  Adhoc execution is disabled while the global (root) organization is selected.
  Switch to a specific organization first. Every run is recorded on [Execution
  History](/features/workbench/job-center/execution-history).
</Alert>
