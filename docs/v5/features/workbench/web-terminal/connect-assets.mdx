# Connect Assets

<Alert type="xpack">
  **Oracle, SQL Server, ClickHouse, Dameng, and OceanBase database assets**
  require JumpServer Enterprise Edition. **Desktop database, RDP, VNC,
  RemoteApp, and VirtualApp connection methods** also require Enterprise
  Edition. Web-based built-in terminal, Remote Desktop, and Community-supported
  database access are included in Community Edition.
</Alert>

The Web Terminal connects to assets authorized for your account. A connection is
defined by three choices: the **asset type**, the **protocol**, and the
**connection method**. The method decides whether the session runs in the browser
or in JumpServer Client on your computer.

## Connection flow

1. Select the target asset in the left sidebar. The connection dialog opens.
2. Choose a **Protocol** tab. Assets with multiple protocols, such as SSH and
   SFTP, show one tab per protocol.
3. Choose an **Account** authorized for the asset. **Manual input** lets you enter
   an account and password yourself.
4. Choose a **Connection method**. Methods are grouped as built-in, application,
   and remote application.
5. Open **Advanced options** when you need to change the character set, terminal
   behavior, resolution, application, or the way a remote application opens.
6. Select **Connect**, or **Open in client** for a method that runs in JumpServer
   Client.

## Supported asset types and protocols

The platform of an asset determines which protocols it can enable and which
built-in workspace it opens. For example, a MySQL database uses the `mysql`
protocol, and a Kubernetes cloud asset uses `k8s`.

| Asset type        | Common platforms                                                                                   | Protocols that can be enabled                                                                                                              |
| ----------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Host              | Linux, Unix, macOS, BSD, AIX, Other                                                                | SSH, SFTP, Telnet, VNC, RDP                                                                                                                |
| Windows host      | Windows, Windows-TLS, Windows-RDP                                                                  | RDP, SSH, SFTP, VNC, WinRM                                                                                                                 |
| Network device    | General, Cisco, Huawei, H3C, Switch, Router, Firewall                                              | SSH, Telnet, SFTP                                                                                                                          |
| Database          | MySQL, MariaDB, PostgreSQL, Oracle, SQL Server, DB2, Dameng, OceanBase, ClickHouse, MongoDB, Redis | The matching database protocol, such as `mysql`, `postgresql`, `oracle`, `sqlserver`, `db2`, `dameng`, `clickhouse`, `mongodb`, or `redis` |
| Cloud service     | Kubernetes                                                                                         | k8s                                                                                                                                        |
| Cloud service     | Public cloud, Private cloud                                                                        | HTTP                                                                                                                                       |
| Web               | Website                                                                                            | HTTP or HTTPS                                                                                                                              |
| Directory service | General, Windows Active Directory                                                                  | SSH, RDP, VNC, WinRM                                                                                                                       |
| Custom type       | Administrator-defined                                                                              | Custom protocol                                                                                                                            |

The connection dialog only lists protocols and methods that are enabled on the
platform, licensed, and authorized for the current account. Two assets of the
same type can therefore show different choices.

## Connection methods

Available methods depend on the asset protocol, enabled components, license, and
the methods assigned to your account.

| Method                  | Where the session runs                                                                                        | Common examples                                                                                        | Requirements                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| **Built-in**            | In the browser, rendered by JumpServer                                                                        | Terminal, Web CLI, Database Workbench, Remote Desktop, VNC, File Manager, Kubernetes, Built-in Browser | The component for the protocol is enabled; no local client is needed                                  |
| **Application**         | In a local application launched by JumpServer Client                                                          | SSH Client, SSH Guide, SFTP Client, DB Client, DB Guide, Remote Desktop, VNC Client, VNC Guide         | JumpServer Client installed; the local application path configured in Settings > Application Settings |
| **Remote Application**  | In a published application, in the browser or in JumpServer Client when the **Client** option is chosen       | DBX, Navicat, WebLite, and other published applications                                                | The application is published on a RemoteApp machine; the account is authorized                        |
| **Virtual Application** | In a published Linux application, in the browser or in JumpServer Client when the **Client** option is chosen | VirtualApp images published by the Panda application provider                                          | VirtualApp is enabled, a provider is registered, and the application is published                     |

![Figure 3: Connection method categories](/images/v5/jumpserver/v5_user_wb_luna_15.png)

### Built-in

JumpServer renders the session in the browser. Use a built-in method when you do
not need a local tool, when the client is unavailable, or when an access control
policy restricts client methods. See
[Browser workspace by protocol](#browser-workspace-by-protocol) for what each
protocol opens.

### Application

The Application method hands the connection to a local program through
JumpServer Client. Select a native method such as **SSH Client**, **SFTP Client**,
**DB Client**, **Remote Desktop**, or **VNC Client**, then select **Open in
client**. The client starts or focuses the configured application and passes the
asset, account, and connection details to it.

Before using this method, install JumpServer Client and configure the application
path for the protocol in
[Settings > Application Settings](/features/client/connection-settings#application-settings).
Desktop database, RDP, and VNC application methods require JumpServer Enterprise
Edition.

### Remote Application and Virtual Application

Remote Application and Virtual Application open an application published by an
administrator instead of a raw protocol session. They are the normal path for
Windows applications on a RemoteApp machine and for Linux applications in a
Panda-provided VirtualApp environment.

RemoteApp and VirtualApp both appear under the **Remote Application** method
group. Select the published application, then use **Advanced options** to choose
the browser path or the **Client** path.

By default the published application opens in the browser. When the connection
dialog offers a **Client** option under **Advanced options**, select **Client** to
open the published application in JumpServer Client instead. This is useful when
the local application window, local input devices, or a client-only integration is
required.

### When JumpServer Client opens

The browser Web Terminal starts JumpServer Client in these cases:

1. **Application method** — any native method, such as **SSH Client**,
   **SFTP Client**, **DB Client**, **Remote Desktop**, or **VNC Client**. The
   primary button reads **Open in client**, and the session runs in the local
   application.
2. **Remote Application or Virtual Application with the Client option** — open
   **Advanced options**, select **Client**, and connect. The published
   application opens in JumpServer Client instead of the browser.

The client must be installed, running, and able to reach JumpServer. For
Application methods, the matching local application must also be configured in
Settings. If the client is missing or the application path is not configured, the
launch fails; select a built-in method or configure the client first.

If an access control policy disables client connection methods, the connection
dialog offers only built-in methods, and the client cannot be used for that asset.

### Web assets and the built-in browser

A **Website** asset in the browser Web Terminal opens through a published
**WebLite** remote application. The JumpServer Client built-in browser is a
separate client-only path: it needs no RemoteApp publisher, Windows Server, or RDS
license, and it is included in Community Edition. See
[Web assets](/features/console/assets/web-assets) for both paths.

## Session management

Sessions open as tabs in the session area.

- Switch sessions with `Alt + Shift + ← / →` or `Ctrl + 1–9`.
- Drag tabs to reorder them.
- Drop one tab onto another to group them; grouped tabs can be restored in a future
  session. See
  [Web Terminal Settings](/features/workbench/web-terminal/settings).
- Right-click a tab for pure mode, full screen, duplicate window, reconnect,
  rename, vertical split, horizontal split, and close actions.
- Use **New Connection** to reopen a recent asset, or **Transfer Center** to review
  file transfers.

## Notes

- If the connection dialog reports no available account, ask an administrator to
  check the account authorization.
- If a protocol is missing, the asset platform may not support it or the asset was
  not created with that protocol enabled.
- If an application method is missing, install JumpServer Client and configure the
  local application path. If a client method is disabled, an access control policy
  may be blocking it.
