# Approval Workflows

<Alert type="xpack">
  **Tickets & Approvals** requires JumpServer Enterprise Edition. Ticket
  entries, approval cards, and flow settings are hidden without a license.
</Alert>

**Approval workflows** is the administrative configuration view for ticket approval. It
defines the approval path a request follows, who approves at each node, and who is
copied on the ticket. It is not where access is requested: applicants
create requests from [Submitted](/features/workbench/tickets/my-tickets), and
approvers act on them from [Related to me](/features/workbench/tickets/awaiting-approval).

![Figure 1: Approval workflows list.](/images/v5/jumpserver/v5_ticket_flow_list_01.png)

## Prerequisites

- The Tickets feature is enabled and licensed. The **Tickets & Approvals** area
  requires an enterprise license.
- Your role grants the ticket flow permissions needed to view, create, update, or
  delete flows. Managing flows is an administrative task, not part of the normal
  applicant workflow.

## Review existing flows

The list shows the flows available in the current organization, including flows
inherited from the global organization.

| Column       | Description                         |
| ------------ | ----------------------------------- |
| Name         | Flow name                           |
| Type         | Ticket type the flow applies to     |
| Organization | Organization that owns the flow     |
| Version      | Published workflow version          |
| Enabled      | Whether the flow is enabled         |
| Update date  | Last modification time              |
| Actions      | Edit, duplicate, or delete the flow |

## Create a flow

<Steps>

<div>Open **Approval workflows** and click **Create**.</div>

<div>
  In **Basic information**, enter a **Workflow name**, select the **Request
  type**, and optionally add a **Description**.
</div>

<div>
  Build the **Workflow** canvas. A flow starts at **Start** and ends at **End**.
  Add **Approval**, **Condition**, and **CC** nodes and connect them in the
  order the request should follow.
</div>

<div>
  Select a node to edit **Node settings**. For an **Approval** node, set the
  **Node name**, **Approver source**, **Approval strategy**, timeout and
  approval actions, and the **Next node**.
</div>

<div>
  Click **Publish workflow** to make the flow available for the request type. A
  flow stays in **Draft** until it is published.
</div>

</Steps>

| Area              | Setting                      | Description                                                               |
| ----------------- | ---------------------------- | ------------------------------------------------------------------------- |
| Basic information | Workflow name                | Required name of the flow.                                                |
| Basic information | Request type                 | Ticket type that uses the flow, for example **Apply for assets**.         |
| Basic information | Description                  | Optional explanation of when to use the flow.                             |
| Workflow          | Start and End                | Fixed entry and exit nodes; every path ends at **End**.                   |
| Workflow          | Approval                     | Waits for a decision from the configured approvers.                       |
| Workflow          | Condition                    | Branches to a different path based on ticket data.                        |
| Workflow          | CC                           | Adds users who receive updates but do not approve.                        |
| Node settings     | Node name                    | Name shown on the selected node.                                          |
| Node settings     | Approver source              | Organization administrators, specified users, or an attribute-based rule. |
| Node settings     | Approval strategy            | Whether any one approver or all approvers must agree.                     |
| Node settings     | Timeout and approval actions | What happens when the node is not decided within the configured time.     |
| Node settings     | Next node                    | Node that follows the current node on this path.                          |

### Approval modes and conditions

<VersionBadge version="5.2.0" />

A flow can combine approval nodes with conditional branches and choose how each node reaches a decision:

- **Approval modes** â€?an approval node can require all approvers or any one approver.
- **Conditions** â€?branch to different approval paths based on the ticket data.
- **Reassignment and additional approvers** â€?move a pending approval to another handler or add approvers while the ticket is in progress.
- **Timeout handling** â€?define what happens when a node is not approved within the configured time.

## How a flow is selected

When an applicant creates a ticket, JumpServer chooses an approval flow from the
selected organization and the ticket type. If only one flow matches, it is filled
in automatically; when several match, the applicant can choose from the available
flows. The chosen flow determines the number of approval steps, the handlers at
each step, and the CC list shown on the ticket.

Ticket approvals cover asset authorization, login review, command review, asset
connect review, account password viewing and changes, file uploads and downloads,
and session recording downloads. See
[Ticket types](/features/workbench/tickets/my-tickets#ticket-types) for the full
list. Approved authorization tickets can request an authorization renewal with a
new authorization period.

<Alert type="note">
  Legacy tickets and workflows are migrated automatically. Complex approver
  rules may be disabled during migration and require review before they are used
  again.
</Alert>
