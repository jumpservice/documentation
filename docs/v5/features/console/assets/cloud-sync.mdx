# Cloud Sync

<Alert type="xpack">
  **Cloud sync** requires JumpServer Enterprise Edition. The menu entry is
  hidden when the license is missing or the account lacks cloud sync
  permissions.
</Alert>

**Cloud sync** imports hosts and database instances from cloud platforms and
keeps the JumpServer asset inventory aligned with the instances that actually
exist. A cloud account stores the platform credentials and sync task settings, a
sync policy decides which instances are imported, and the **Synchronize
instance** tab shows what the last run produced.

Cloud sync is available from the host and database asset lists. Open the asset
category you need and select **Cloud sync**.

![Figure 1: Cloud sync entry in the asset list.](/images/v5/jumpserver/v5_cloud_sync_entry_01.png)

## Overview

Cloud sync is organized around a cloud account and the policy that controls it.
The **Accounts** tab stores the provider credentials, region, and sync settings.
The **Sync policy** tab defines the ordered rules that decide which instances are
imported or skipped and which actions apply; a built-in default policy exists and
cannot be deleted. After a run, the **Synchronize instance** tab shows which
instances were discovered, imported, or skipped.

## Before you begin

- Sign in with an account that can manage assets and cloud sync.
- Have credentials for the cloud platform, and make sure JumpServer can reach the
  platform API endpoint.
- Decide which regions and instances should be imported, and which node in the
  asset tree should receive them.

<Alert type="note">
  Until a cloud account is configured, the **Synchronize instance** tab stays
  empty. Create the account first, then review the policy, then run the sync.
</Alert>

## Create a cloud account

<Steps>
<div>
Open the **Accounts** tab and click **Create**.
</div>

<div>Select the provider in the wizard and click **Next**.</div>

<div>
  In the **Authentication** step, enter the credentials and region details.
</div>

<div>
In the **Sync** step, select the instances to import and the node that should
receive them, then review the **Result** step and submit.
</div>
</Steps>

![Figure 2: Cloud sync provider selection.](/images/v5/jumpserver/v5_cloud_sync_provider_01.png)

After the account is created, use its detail page to adjust the sync task:

- the source IP type, public or private;
- whether released instances are removed from the inventory;
- whether existing assets are always updated;
- the sync **Timer**, either a periodic interval or a crontab;
- the sync policy relation.

## Work with sync policies

A sync policy is an ordered set of rules. Each policy has a name, a priority,
rules that match instances, actions applied to matched instances, and a rule
relation (all or any). Lower priority values are evaluated earlier. Keep policies
narrow: one policy per platform or region is easier to troubleshoot than a single
policy that spans many environments.

<Steps>
<div>
Open the **Sync policy** tab and click **Create**.
</div>

<div>In **Create sync policy**, enter a **Name** and **Priority**.</div>

<div>
Add the rules and actions, choose the rule relation, then click **Submit**.
</div>
</Steps>

![Figure 3: Create sync policy drawer with conditions and actions.](/images/v5/jumpserver/v5_cloud_sync_policy_01.png)

## Review sync results

<Steps>
<div>
Run the sync, or wait for the scheduled run to start.
</div>

<div>
  Open the **Synchronize instance** tab to review the discovered instances and
  their status.
</div>

<div>
Return to the asset category that owns the instances and confirm that the
expected assets now appear.
</div>
</Steps>

Synced assets behave like manually created assets: they can be added to nodes,
bound to accounts, and authorized. If an asset does not appear, check the policy
rules first, then the account's connection state, and finally whether the
instance already exists under a different address.

## Database synchronization

<VersionBadge version="5.2.0" />

Tencent Cloud database synchronization imports MySQL, PostgreSQL, and SQL Server
database instances. Create the cloud account from the **Database** category,
select the Tencent Cloud provider, and choose the instances to import. Synced
instances become database assets that can be authorized like manually created
assets.

## Pending review

<VersionBadge version="5.2.0" />

Each sync run reports its progress, discovered changes, and errors. When a scan is
incomplete, affected assets enter a **pending review** state instead of being
released immediately. This prevents an incomplete scan from removing assets that
still exist in the cloud account.
