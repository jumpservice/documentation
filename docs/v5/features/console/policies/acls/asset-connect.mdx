# Asset Connect

<Alert type="xpack">
  **Asset connection control** requires JumpServer Enterprise Edition.
</Alert>

**Asset Connect** controls asset connections based on the source IP address and
time of day. An authorization decides whether a user may reach an asset at all;
an asset connect control adds a second gate that can reject the connection when
the request comes from an unexpected network or outside an allowed window.

Open the page from **Console > ACLs > Asset Connect**.

## Overview

Each rule matches a user, an asset, an account, and a time/IP condition. Rules are
evaluated by priority: the lower the number, the earlier the rule is matched, and
the first matching rule supplies the action. Rules are scoped to the current
organization.

![Figure 1: Asset connect ACLs list with name, priority, active state, and actions.](/images/v5/jumpserver/v5_admin_acls_06.png)

## Before you begin

- Sign in with an account that can manage ACLs.
- Review existing [Authorizations](/features/console/policies/authorizations) so the new
  control does not duplicate or contradict them.
- Plan the allowed source networks and time windows before enabling a reject
  rule.

### Field reference

| Group    | Field       | Description                                                                                                                                   |
| -------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Basic    | Name        | Required. Rule name, unique within the organization.                                                                                          |
| Basic    | Priority    | Integer from 1 to 100. Defaults to 50; the lower the value, the earlier the rule is matched.                                                  |
| Users    | Users       | **All users**, **Specified users**, or **Attribute filter**.                                                                                  |
| Assets   | Assets      | **All assets**, **Specified assets**, or **Attribute filter**.                                                                                |
| Accounts | Accounts    | **All accounts** or **Specified accounts**.                                                                                                   |
| Rule     | IP          | Source IP restriction. `*` matches all. Single addresses, CIDR ranges, address ranges, and IPv6 are supported; press Enter to add each entry. |
| Rule     | Time period | Drag to select weekdays and hours. No selection means all day, every day.                                                                     |
| Action   | Action      | **Allow** applies the enabled connection controls; **Reject** blocks the connection. Defaults to **Reject**.                                  |
| Other    | Active      | When selected, the rule takes effect.                                                                                                         |
| Other    | Comment     | Optional.                                                                                                                                     |

## Connection controls

The **Allow** action can apply one or more connection controls. Select the controls
in the create or edit drawer; they are cumulative for the request and cover the
period before, during, and after the connection.

| Stage          | Control           | What it does                                                                                                                                                                                                                                           |
| -------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Before connect | Connection reason | Requires the user to enter a reason (request justification) before the connection starts. The reason is kept with the request and approval.                                                                                                            |
| Before connect | MFA verification  | Requires an enrolled code-based MFA method. The connection is blocked when no code-based MFA method is enrolled.                                                                                                                                       |
| Before connect | Face verification | Verifies the user's face before connecting. Requires system face recognition and an enrolled face.                                                                                                                                                     |
| Before connect | Require approval  | Requires approval through the selected workflow or approvers. See [Approval Workflows](/features/workbench/tickets/ticket-flow) to configure a workflow. The approval exemption period can skip repeat approval for the same user, asset, and account. |
| Before connect | Push account      | Provisions a same-name account before its first connection. Requires account provisioning support on the asset platform.                                                                                                                               |
| Before connect | Send notification | Notifies the selected recipients when the user requests a connection. A notification does not approve or block the request.                                                                                                                            |
| During connect | Face online       | Web Terminal only. Verifies the face before connecting and monitors the session. Requires system face recognition and an enrolled face.                                                                                                                |
| After connect  | Rotate password   | Rotates the connected account's secret after the session ends. Requires automatic rotation after session end and an active account.                                                                                                                    |

Controls can be combined, for example connection reason + MFA + approval + rotate
password. Requirements can apply before, during, or after the connection; failing
any required check blocks the connection. Approval and notification recipients,
face recognition, and post-session rotation also need their system settings and
license to be enabled.

## Approval exemption period

When **Require approval** is enabled, choose how connections are approved and
whether an approved connection can be reused without another approval.

### Approval mode

| Mode              | Configuration                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| Simple approval   | Select one or more **Approvers**. The connection is blocked when no approver is available.        |
| Workflow approval | Select an enabled asset connection workflow. The workflow defines the approval path and handlers. |

### Exemption period

The **Exemption period** is measured in hours. `0` requires approval for every
connection. After an approval, the same user can reconnect to the same asset with
the same account without another approval until the period ends.

The exemption is tied to the specific user, asset, and account combination. A
different user, asset, or account still goes through approval, and the next
connection after the period ends requires approval again. Changing the exemption
period does not affect exemptions that were already granted.

Use `0` for sensitive assets that must be approved every time, and a short period
for troubleshooting sessions that may reconnect several times.

![Figure 2: Approval mode, approvers, and exemption period in the asset connect drawer.](/images/v5/jumpserver/v5_console_acl_asset_connect_approval.png)

## Test before enabling

1. Create the rule with a narrow scope: one user or one asset, and a test IP.
2. Keep **Active** selected and attempt a connection from an allowed and from a
   blocked address.
3. Confirm the expected result in the user's session and in
   [Login Logs](/features/audits/activities/login-logs).
4. Widen the user or asset scope only after the behavior is confirmed.

<Alert type="warning">
  When an active rule returns **Reject**, matching users cannot connect to the
  assets even when an authorization exists. Make sure the rule's users, assets,
  and IP scope are as narrow as the scenario requires.
</Alert>

<Alert type="note">
  The **Allow** and **Reject** actions are always available. The connection
  controls on an **Allow** rule depend on the edition, license, and enabled
  system features; for example, face verification requires face recognition and
  post-session rotation requires automatic rotation after session end.
</Alert>
