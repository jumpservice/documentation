# System Tools

System Tools provides a set of network diagnostics that run from the JumpServer
host. Use it to check whether an asset is reachable before you troubleshoot a
connection, and to confirm which port or route is failing.

## Overview

| Tool | Purpose |
| --- | --- |
| `ping` | Check whether a host responds to ICMP, confirming basic reachability and latency. |
| `telnet` | Test whether a specific TCP port accepts a connection, for example SSH on port `22` or RDP on port `3389`. |
| `nmap` | Scan a host for open ports and identify exposed services. |
| `tcpdump` | Capture traffic on the JumpServer host to inspect packet loss or protocol errors. |
| `traceroute` | Show the network path to the target and locate the hop where connectivity breaks. |

## Run a diagnostic

<Steps>

<div>
<Nav name="system-settings" />
</div>

<div>
In the left menu, click **System Tools**.
</div>

<div>
Select the tool tab you need.
</div>

<div>
Enter the target address, and a port when the tool requires one.
</div>

<div>

</div>

## Enable the tools in the workbench

The **Basic** tab contains a single option, **Tools in the workbench**. When it
is enabled, the same diagnostics are also available to users from the
[Workbench tools](/features/workbench/tools) page, which lets operators check
connectivity without entering System Settings.

<Steps>
<div>
Open the **Basic** tab.
</div>

<div>
Select **Tools in the workbench**.
</div>

<div>
Click **Submit**.
</div>
</Steps>

<Alert type="note">
The commands run on the JumpServer server, not in the user's browser. Traffic
therefore originates from the JumpServer host network and is subject to the same
routing, firewall, and proxy rules as any other JumpServer connection. Tools that
are not installed in the runtime image, or that lack the required kernel
capabilities, are not available even when the feature is enabled.
</Alert>
