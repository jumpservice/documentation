# System Tasks

System Tasks shows everything that JumpServer runs in the background and lets
you control how long the resulting records are kept. Scheduled automations,
periodic synchronizations, and cleanup jobs are all listed here.

## Overview

The page has two tabs:

| Tab              | Purpose                                                                 |
| ---------------- | ----------------------------------------------------------------------- |
| Tasks            | Scheduled tasks, their state, execution history, and worker monitoring. |
| Regular clean-up | Retention periods for logs, activity records, and execution history.    |

## Task list

| Column              | Description                                                                |
| ------------------- | -------------------------------------------------------------------------- |
| Name                | Task name. For scheduled tasks, the subtitle describes what the task does. |
| Success / Total     | Number of successful executions against the total.                         |
| Status              | Current task health indicator.                                             |
| Release date        | When the task was last dispatched.                                         |
| Periodic executor   | Cron expression or interval for periodic tasks.                            |
| Next execution time | Planned time of the next run.                                              |
| Enable              | Switch that enables or disables a periodic task.                           |

Typical entries include account backup plans, account pushes, connectivity
checks, email delivery, directory synchronization, and cloud synchronization.
Click a task name to open its detail page with the full execution history and
logs.

### Celery logs

<VersionBadge version="5.1.0" kind="changed" />

Celery logs are consolidated into a single window with separate tabs. Switch
between the tabs to read the logs of different tasks instead of opening one
window per task.

### Manage task execution

<VersionBadge version="5.2.0" kind="new" />

From the task list, cancel a pending task that no longer needs to run, or terminate
an eligible running task when it must stop. For current worker and queue state,
see [Monitoring](#monitoring). Terminating a running task
can leave part of its work unfinished; review the task log and rerun the task if
needed.

## Monitoring

<VersionBadge version="5.2.0" kind="new" />

Open **Monitoring** from the **Tasks** toolbar. The page shows the Celery workers
and queues that execute background work and has its own **Workers** and **Tasks**
tabs. The page refreshes every 10 seconds while it is visible; if a
sample is old, the page marks it as stale. The **Tasks** tab returns to the task
list.

### Workers

The summary cards show **Responding workers**, **Active**, **Reserved**,
**Scheduled**, and **Queued** counts. The worker table shows each worker's status,
processed, success, failure, and retry counts, current task states, load average,
concurrency, and queues.

- **No response** means the worker did not reply to this sample; it does not prove
  that the worker is offline.
- Processed, success, failure, and retry counts accumulate since the worker
  started and reset when it restarts.
- A dash means the value is unavailable. Load average covers the last 1, 5, and
  15 minutes.

### Queue backlog

The queue backlog shows how many tasks are waiting in each queue. Queued tasks
are waiting in the broker and cannot be canceled from this page; reserved tasks
are held by workers, and scheduled tasks are waiting for their ETA.

### Worker tasks

Select a worker to inspect its **Active**, **Reserved**, and **Scheduled** tasks.
The list shows the task ID, name, start time, and acknowledgment state. Depending
on permissions, **Output** opens the task output and **Execution History** opens
the related execution history. The page shows up to the configured sample limit
per worker and state.

## Regular clean-up

Retention is configured per record type. The defaults are suitable for most
deployments; shorten them when local storage grows quickly, and lengthen them
when audit requirements demand it.

| Record type                 | What is deleted                                         |
| --------------------------- | ------------------------------------------------------- |
| Login log                   | User sign-in records.                                   |
| Task log                    | Automated task execution records.                       |
| Operate log                 | User operations on assets and resources.                |
| Password change log         | Password change history.                                |
| Upload / download log       | FTP file transfer records.                              |
| Session log                 | Session records, command records, and local recordings. |
| Activity log                | Activity records shown on resource detail pages.        |
| Job execution               | Job center execution history.                           |
| Cloud sync task execution   | History of asset cloud synchronization runs.            |
| Change secret / push record | Account secret changes and account pushes.              |

![Figure 3: Regular clean-up settings.](/images/v5/jumpserver/v5_settings_system_tasks_cleanup_01.png)

<Alert type="warning">
  Clean-up settings control local records only. Recordings or command logs that
  are stored in external storage are governed by the retention policy of that
  system, and files already removed by a cleanup task cannot be recovered.
  Verify backups before you shorten a retention period.
</Alert>
