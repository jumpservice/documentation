# Asset Connection

<Alert type="xpack">
  **Oracle, SQL Server, DB2, ClickHouse, Dameng, and OceanBase database assets**
  require JumpServer Enterprise Edition. **Desktop database, RDP, VNC,
  RemoteApp, and VirtualApp connection methods** also require Enterprise
  Edition. Desktop SSH and SFTP connections are included in Community Edition.
</Alert>

JumpServer Client is the local endpoint for authorized assets. It opens
connections directly from its asset list, and it is also the process that opens
when the browser Web Terminal uses an **Application** method or a published
application with the **Client** option.

## Connection flow

1. Find the asset in the client asset list.
2. Select **Connect** next to the asset name.
3. Choose a **Protocol**, an authorized **Account**, and a **Connection method**. Methods are grouped as built-in, application, and remote application.
4. Select **Confirm**. The session opens in the client window or in the local
   application, depending on the method.

![Figure 1: Unified connection entry with JumpServer Client.](/images/v5/jumpserver/v5_client_asset_entry_01.png)

## Supported asset types and protocols

The asset platform determines which protocols and methods are available. The
client uses the same asset catalog as the Web Terminal.

| Asset type        | Common protocols                                                                                   | What the client opens                                                                        |
| ----------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Linux and Unix    | SSH, SFTP, VNC                                                                                     | Built-in terminal, File Manager; Application SSH/SFTP/VNC clients                            |
| Windows           | RDP, VNC, SSH, SFTP, WinRM                                                                         | Built-in Remote Desktop and terminal with PowerShell over WinRM; Application RDP/VNC clients |
| Kubernetes        | k8s                                                                                                | Built-in Kubernetes workspace                                                                |
| Database          | MySQL, MariaDB, PostgreSQL, Oracle, SQL Server, DB2, Dameng, OceanBase, ClickHouse, MongoDB, Redis | Built-in Database Workbench; Application DB client; Remote Application DBX/Navicat           |
| Web               | HTTP, HTTPS                                                                                        | Built-in Browser                                                                             |
| Directory service | SSH, RDP, VNC, WinRM                                                                               | Built-in terminal and Remote Desktop                                                         |
| Published apps    | RemoteApp, VirtualApp                                                                              | Remote Application (RemoteApp) or Virtual Application (VirtualApp)                           |

The same platform rules as the Web Terminal apply: a protocol must be enabled on
the platform, and the component, license, and authorization must allow it. See
[Supported asset types and protocols](/features/workbench/web-terminal/connect-assets#supported-asset-types-and-protocols)
in the Web Terminal chapter for the full protocol list.

## Connection methods

| Method                  | Where the session runs                                                                                         | Common examples                                                                          | Requirements                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Built-in**            | In the client window, rendered by JumpServer                                                                   | Terminal, Database Workbench, Remote Desktop, File Manager, Kubernetes, Built-in Browser | The component for the protocol is enabled; no local application is needed                           |
| **Application**         | In a local application launched by JumpServer Client, or shown as connection details for **Connection Wizard** | SSH Client, SFTP Client, DB Client, Remote Desktop, VNC Client, and Connection Wizard    | JumpServer Client and the local application path for direct launch; Connection Wizard needs neither |
| **Remote Application**  | In a published application, in the client window, or in the browser when started from the Web Terminal         | DBX, Navicat, WebLite, and other published applications                                  | The application is published on a RemoteApp machine; the account is authorized                      |
| **Virtual Application** | In a published Linux application, in the client window, or in the browser when started from the Web Terminal   | VirtualApp images published by the Panda application provider                            | VirtualApp is enabled, a provider is registered, and the application is published                   |

### Built-in

Use the Built-in method when you do not need a local program. The client renders
the session in its own window, so it keeps the client's layout, tabs, and session
controls. This is also the fallback when a local application is not installed or
an access control policy blocks client methods.

### Application

The Application method hands the connection to a local program through JumpServer
Client. Select a native method such as **SSH Client**, **SFTP Client**, **DB Client**,
**Remote Desktop**, or **VNC Client**, and the client starts or focuses the
configured application. Configure the application path in
[Settings > Application Settings](/features/client/connection-settings#application-settings)
before using this method.

### Connection Wizard

The **Connection Wizard** is an Application method that returns the connection
details instead of launching a local program. After you select the asset, the
account, and **Connection Wizard**, JumpServer displays:

- the JumpServer proxy address and port to connect to;
- a temporary username and password for this connection;
- the ready-to-copy connection information for the selected protocol.

Use these details in any compatible SSH, database, RDP, or VNC client on your
computer. The client connects to the JumpServer proxy rather than directly to the
asset, so authorization, access control, and auditing still apply. The temporary
credentials and the proxy endpoint expire with the connection; do not save or
share them.

Connection Wizard does not launch a local application or JumpServer Client. Use it
when no local application is configured, when you prefer a different client, or
when you need to pass the connection details to another tool.

### Remote Application and Virtual Application

Remote Application and Virtual Application open an application published by an
administrator instead of a raw protocol session. They are the normal path for
Windows applications on a RemoteApp machine and for Linux applications in a
Panda-provided VirtualApp environment.

RemoteApp and VirtualApp both appear under the **Remote Application** method
group. When you open one from the client asset list, the published application
opens in the client window. When the Web Terminal hands it off with the **Client**
option, it opens in the client in the same way.

## When JumpServer Client opens

The browser Web Terminal starts JumpServer Client in these cases:

1. **Application method** — a native method that launches a local application,
   such as **SSH Client**, **SFTP Client**, **DB Client**, **Remote Desktop**, or
   **VNC Client**. The client opens the configured local application with the
   selected asset and account.
2. **Remote Application or Virtual Application with the Client option** — when
   the Web Terminal connection dialog offers **Client** under **Advanced
   options**, selecting it opens the published application in JumpServer Client.

**Connection Wizard** is not one of these cases: it returns connection details and
does not launch JumpServer Client.

When the client is launched this way, it receives the selected asset, account, and
protocol from the Web Terminal. The client must be installed, running, and able to
reach JumpServer; for an Application method, the local application path must
already be configured. See the
[Web Terminal connection rules](/features/workbench/web-terminal/connect-assets#when-jumpserver-client-opens)
for the full conditions and fallback behavior.

## Connect to specific assets

### Linux and Unix assets

1. Select **Connect** next to the Linux asset.
2. Choose **SSH**, **SFTP**, or **VNC**.
3. Select an authorized account and confirm.

Run commands and upload or download files in the session after it connects.

![Figure 2: Linux asset connection dialog with SSH and SFTP options.](/images/v5/jumpserver/v5_client_linux_connection_01.png)

### Windows assets

1. Select **Connect** next to the Windows asset.
2. Choose **RDP**, **VNC**, **SSH**, or **WinRM**.
3. Select the account and confirm the connection.

Windows PowerShell sessions over WinRM open in the built-in terminal. RDP and VNC
can use either the built-in Remote Desktop or a configured local client.

![Figure 3: Windows asset connection dialog with RDP and WinRM options.](/images/v5/jumpserver/v5_client_windows_connection_01.png)

### Kubernetes assets

Kubernetes cloud assets use the `k8s` protocol. Select the asset, choose the
authorized account, and confirm. The Kubernetes workspace opens in the client
with a resource browser and a container terminal.

### Database assets

Database assets can open in Database Workbench or in a configured local database
client. To use a local client, configure its executable path in
[Settings > Application Settings](/features/client/connection-settings#application-settings)
first, then choose the Application method for that database asset.

The database platforms support the same options as in the Web Terminal: DB2 and
ClickHouse open in Database Workbench, ClickHouse can enable both HTTP and Native,
Redis Cluster connects through a single endpoint, OceanBase provides
MySQL-compatible and Oracle-compatible tenant platforms, and SQL Server domain
accounts authenticate with NTLMv2 or Kerberos.

![Figure 4: Database connection dialog for a PostgreSQL asset.](/images/v5/jumpserver/v5_client_database_connection_01.png)

### Web assets

Web assets use the **Website** platform and the **HTTP** or **HTTPS** protocol.

1. Select **Connect** on the web asset.
2. Choose **Built-in** > **Built-in browser**.
3. Select the authorized account and confirm.

The site opens in the client's WebView window and traffic is forwarded through the
JumpServer Web proxy on `5001/tcp`. The built-in browser is available only in
JumpServer Client; the browser Web Terminal uses a published WebLite application
instead. This path needs no RemoteApp publisher, Windows Server relay, or RDS
license, and is included in Community Edition.

![Figure 5: Web asset connection dialog with the built-in browser selected.](/images/v5/jumpserver/v5_client_web_browser_01.png)

The site address, account, and autofill method are configured on the asset in
**Console > Assets > Web**. The client does not provide an edit entry for them.
Web session recording requires recording storage and JumpServer Enterprise
Edition; see [Web assets](/features/console/assets/web-assets).

## Site security

<VersionBadge version="5.2.0" />

For web assets, the built-in browser validates the site certificate over HTTPS by
default. When a certificate is not trusted, the client shows the certificate
details so you can review them before you continue.

- Site-specific certificate exceptions can be added for sites that use a
  certificate the client does not trust by default.
- Opening a site over plain HTTP shows a risk confirmation before the page loads.

Review exceptions periodically and remove them when a site has a trusted
certificate again.

## Notes

- Connection methods and protocols depend on the asset platform, enabled
  components, license, and the account authorization.
- If the client was launched from the Web Terminal but the application did not
  open, confirm that the client is installed and that the application path is
  configured in Settings.
- If an asset or account is missing, ask an administrator to review your
  authorization.
