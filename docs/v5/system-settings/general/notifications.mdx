# Notifications

<Alert type="xpack">
**Message templates and SMS notifications** require JumpServer Enterprise Edition. Email and Subscription notifications are included in Community Edition.
</Alert>

Notifications controls how JumpServer talks to users outside the console. It
covers the email account used for transactional messages, SMS delivery for
verification codes and password recovery, and the subscription rules that decide
who receives platform alerts.

## Overview

The page has separate tabs for each delivery channel:

| Tab | Purpose |
| --- | --- |
| Email | Outgoing mail server used for account, authorization, and security messages. |
| Msg Template | Custom message templates for email and in-site notifications. |
| Message | SMS provider used for SMS verification codes and password recovery. |
| Subscription | Message types, recipients, and delivery channels for platform monitoring alerts. |

## Configure the email service

Email is strongly recommended: account activation, password reset, authorization
expiry, and security alerts all rely on it.

<Steps>

<div>
<Nav name="system-settings" />
</div>

<div>
In the left menu, click **Notifications**.
</div>

<div>
Open the **Email** tab and enter the mail server settings described in the field
reference.
</div>

<div>
Enter a test address in **Recipient**, then run the email test to confirm that
the server accepts the configuration.
</div>

<div>
Click **Submit**.
</div>

</Steps>

![Figure 1: Email settings](/images/jumpserver/V4_systemsetting_notification_settings1.png)

## Email field reference

| Field | Description |
| --- | --- |
| Service | `SMTP` for a standard mail server, or `Microsoft Exchange Server`. |
| Host | Host name or address of the mail server. |
| Port | SMTP port, for example `465` for implicit TLS or `587` for STARTTLS. |
| Account | User name used to authenticate to the mail server. |
| Password | Password for the account. |
| Sender | From address used in outgoing messages. Defaults to the account when empty. |
| Use SSL | `None`, `SSL`, or `TLS`. Select the option that matches the server configuration. |
| Certificate verification | Whether the server certificate is verified, and optionally a custom CA certificate to trust. |
| Email template | Subject prefix and message content used for generated emails. |
| Recipient | Test mailbox used by the email test only. |

## Configure SMS

<Steps>
<div>
Open the **Message** tab and enable SMS.
</div>

<div>
Select the provider: Alibaba Cloud, Tencent Cloud, Huawei Cloud, CMPP v2.0, or a
custom integration.
</div>

<div>
Fill in the provider credentials and set the verification code length, then use
the test button to send a message to your own number.
</div>

<div>
Click **Submit**.
</div>
</Steps>

For SMS-based MFA, each user must first record a phone number in
[Profile](/general/account/profile) and enable SMS as an MFA method. The global
MFA policy is configured in [Security](/system-settings/security/security).

## Configure subscriptions

The **Subscription** tab decides which monitoring messages are delivered and
through which channels. Inbox messages are always delivered; for each message
type you can enable additional backends such as email, and use **Edit
recipient** to choose the users who receive that type.

![Figure 2: Message subscription settings](/images/jumpserver/V4_systemsetting_notification_settings7.png)

<Alert type="note">
Submit the email configuration before testing. The email and SMS services are
used by password recovery, so confirm the
[Site URL](/system-settings/general/basic) is correct as well.
</Alert>
