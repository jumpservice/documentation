# Security

Security defines the guardrails around identity and sessions. It is where you
set brute-force protection, MFA policy, password complexity, and the limits that
apply while a user is connected to an asset.

## Overview

| Tab | Controls |
| --- | --- |
| Auth security | Login verification, inactive-user handling, and MFA behavior. |
| Login restriction | Lockout policy for users and IP addresses, allow and deny lists, and concurrent-login rules. |
| User password | Password lifetime, history, and complexity rules. |
| Asset session | Session sharing, idle and maximum duration limits, and watermarking. |

## Auth security

| Field | Description |
| --- | --- |
| Login CAPTCHA | Adds a CAPTCHA after failed sign-in attempts to slow down automated attacks. |
| Login additional code | Sends the password together with a short additional code to third-party authentication services that expect password plus code. |
| Auto disable threshold (days) | Disables users who have not signed in for the configured number of days. |
| Suspicious login verification | Sends a remote-login alert when a user signs in from an unfamiliar city. |
| Global MFA | `Disabled`, `All users`, or `Only admin users`. When enabled globally, users cannot turn MFA off by themselves. |
| MFA methods | Selects the verification methods offered to users. |
| MFA in login page | Lets users enter an MFA code together with the password. Requires an Enterprise license. |
| MFA via email | Allows email to be used as an MFA method. Requires the email service. |
| Third-party MFA | Enforces MFA for users who sign in through CAS, OIDC, SAML2, OAuth2, WeCom, DingTalk, Feishu, Lark, or Slack. |
| MFA verify TTL (seconds) | How long an MFA verification remains valid, for example when an administrator views an account secret. |
| OTP issuer name | Display name shown in the authenticator application for generated codes. |
| OTP valid window | Number of adjacent time steps accepted for a one-time password. `0` accepts the current step only. |

## Login restriction

- **User**: after **Login failures count** consecutive failures within **Login
  failure period**, the user is locked until an administrator unlocks it.
- **IP**: after the configured number of failures from one address, every user
  from that address is denied. Locked IPs are listed on the same tab and can be
  released there.
- **Login IP whitelist** and **Login IP blacklist** always allow or always deny
  the listed addresses. Use `*` to match all. To allow only specific addresses,
  set the blacklist to `*` and list the permitted addresses in the whitelist.
- **Only single device login** signs the previous device out when a user signs
  in from a new one.
- **Only existing users** rejects sign-in attempts with unknown user names.
- **Only from the user's source** requires users to authenticate through the
  source recorded on their user profile.

## User password

Password expiration is measured from the last password change. Five days before
expiry, JumpServer emails a daily reminder; after expiry the user cannot sign
in. The recent-password count blocks reuse of previous passwords.

Password rules apply to user passwords only, not to asset account passwords:
minimum length for users and for administrators, plus optional requirements for
uppercase, lowercase, digits, and special characters. The weak-password list is
also used during account risk detection.

## Asset session

| Field | Description |
| --- | --- |
| Session share | Lets users share an active session link with other users for collaborative troubleshooting. |
| Session expire at browser close | Terminates the session when the browser is fully closed. |
| Allow users to view asset session information | Shows the number of active sessions on the asset selection dialog for RDP assets. |
| Max idle time (minute) | Disconnects a session that has been idle for longer than this value. |
| Max online time (hour) | Disconnects a session after it has been open for this long. |
| Watermark | Overlays the signed-in user's details on the console, sessions, and recordings. Content, color, size, and rotation are configurable with an Enterprise license; RDP client sessions do not show a watermark. |

<Alert type="note">
Global MFA and password policy apply to every organization. If MFA is enforced
and administrators cannot sign in, use the documented recovery procedure before
changing the policy. See [Authentication](/system-settings/security/authentication)
and [Passkeys](/general/account/passkeys) for method-specific behavior.
</Alert>
