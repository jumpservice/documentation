# Quickstart

This end-to-end guide takes you from installation to your first authorized asset
session. It combines first login, Console orientation, asset setup, authorization,
connection, and audit into one flow.

You can watch the video below or follow the steps in order.

## Before you begin

You need:

- A running JumpServer installation. See [Installation](/installation).
- The URL of the deployment and the initial administrator account.
- A test asset (for example, a Linux host) that JumpServer can reach.

## Sign in and secure the account

1. Open `https://<jumpserver-host>/` in a current browser.
2. Sign in with the initial account: username `admin`, password `ChangeMe`.
3. Complete the forced password change and sign in again.

<Alert type="warning">
The default password is public. Change it immediately and do not reuse it for
other systems. If MFA is required by the platform policy, complete MFA setup
before continuing.
</Alert>

## Get oriented in Console

After login, the area switcher at the top-left moves between **Console**, **PAM**,
**Audits**, and **Workbench**. System administrators can open **System Settings**
from the gear icon.

Console is the administration workspace. Its left menu is organized as follows:

| Section | Pages | Purpose |
| --- | --- | --- |
| Users | Users, Groups | Identity and group membership |
| Assets | Assets, Zones, Cloud Sync | Asset inventory and network zones |
| Accounts | Accounts, Templates | Privileged account inventory and templates |
| Policies | Authorizations, ACLs | Grant access and constrain commands, connections, masking, and clipboard |
| Others | Tags | Organize and filter resources |

![Console dashboard after first login](/images/jumpserver/v5_admin_dashboard_01.png)

The recommended setup order is: users and groups → assets → accounts →
authorizations → ACLs → verify access from Workbench. The steps below follow that
order for a single test asset.

## Create an asset
<Steps>

<div>
<Nav name="console" />
</div>

<div>
Navigate to the **Console > Assets > Host** tab.
</div>

<div>
Click **Create** to open the platform selection page on the right.
</div>


<div>
Select the **Linux** platform and open the asset creation page.
</div>

<div>
In the **Name** field, type a name for the asset, such as "Demo Linux".
</div>

<div>
In the **IP/Host** field, type the IP address of the asset, such as "172.16.10.110".
</div>

<div>
In the **Linux** field, keep the "Linux" platform selected.
</div>

<div>
In the **Nodes** field, select the "/DEFAULT" node.
</div>

<div>
In the **Accounts** field, click the **Add** and follow the steps in the pop-up to complete the account creation. 
    <Steps stepLevel="2">
    <div>
    In the **Name** field, type a name for the account, such as "root".
    </div>

    <div>
    In the **Username** field, type the username for the account, such as "root".
    </div>

    <div>
    In the **Secret type** field, select "Password".
    </div>

    <div>
    In the **Password** field, type the password for the account.
    </div>

    <div>
    For other fields, keep the default values.
    </div>

    <div>
    click **Confirm**.
    </div>

    </Steps>
</div>

<div>
For other fields, keep the default values.
</div>

<div>
Click **Submit**.
</div>

</Steps>

## Authorize the asset
<Steps>

<div>
<Nav name="console" />
</div>

<div>
Navigate to the **Console > Authorization** page.
</div>

<div>
Click <Icon name="plus" />**Create** to open the authorization creation form on the right-side page.
</div>

<div>
In the **Name** field, type a name for the authorization, such as "Authorize Demo Linux to Administrator".
</div>

<div>
In the **Users** field, select the "Administrator(admin)".
</div>

<div>
In the **Assets** field, select the "Demo Linux".
</div>

<div>
In the **Accounts** field, check only the box for "All existing accounts".
</div>

<div>
For other fields, keep the default values.
</div>

<div>
Click **Submit**.
</div>

</Steps>

## Connect to the asset via the web
<Steps>

<div>
<Nav name="web-terminal" />
</div>

<div>
At this point, the Web Terminal page should be open in a new browser tab.

In the authorization tree on the left side, search for and click the "Demo Linux" asset.
</div>

<div>
An asset connection pop-up will appear, select connection parameters and establish the connection.

    <Steps stepLevel="2">
    <div>
    Select the "SSH" tab, under the "Connect - Demo Linux".
    </div>

    <div>
    In the **Select account** section, Select "root".
    </div>

    <div>
    In the **Connect method** section, Select "Web > Web CLI".
    </div>

    <div>
    Click **CONNECT**.
    </div>
    </Steps>

</div>

<div>
By this time, you should have successfully connected to the asset.
</div>

<div>
Next, you can try executing commands such as `ls -al`, `whoami` or `pwd`, etc.
</div>

<div>
Finally, run `exit` to end the current session.
</div>

</Steps>


## Audit the session
<Steps>

<div>
<Nav name="audits" />
</div>

<div>
Navigate to the **Audits > Asset sessions > Historical sessions** tab.
</div>

<div>
You can view the history of asset connection sessions. 
</div>

<div>
In the **Actions** column, click "Playback" to watch the recording online or "Download" to save it.
</div>

</Steps>


## Audit executed commands
<Steps>

<div>
<Nav name="audits" />
</div>

<div>
Navigate to the **Audits > Session commands** page.
</div>

<div>
You can view all executed commands.
</div>

<div>
Click <Icon name="chevron-down"/> at the end of the row to view the command result.
</div>

</Steps>
