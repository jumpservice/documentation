---
title: "Templates"
description: Maintain reusable script and Playbook templates that Adhoc commands and jobs can reference.
---

**Templates** keeps the scripts and Playbooks that Adhoc commands and jobs reuse.
Write the content once and reference it from many jobs: when the template changes,
the jobs that use it pick up the new version, so the same command does not have to
be maintained in several places. This is the recommended way to standardize
routine checks and configuration scripts.

![Figure 1: The Templates page](/images/jumpserver/v5_admin_wb_tpl_01.png)

The page has two tabs: **Script** for command templates and **Playbook** for
Playbook templates.

## Prerequisites

* The **Job Center** feature is enabled in
  [Feature Settings](/system-settings/general/features).
* Your role grants the permissions for the template type you want to manage.

## Create a script template

<Steps>

<div>
Open the **Script** tab and click **Create**.
</div>

<div>
Enter a **name** and choose the **scope**. A public template is available to
everyone; a private template is visible only to its creator.
</div>

<div>
Choose the **module**, for example Shell, and write the script in the content
editor.
</div>

<div>
Add any **variables** the script uses, with a default value for each.
</div>

<div>
Optionally add a comment, then click **Submit**. Use **Save and continue** to
create several templates in a row.
</div>

</Steps>

![Figure 2: Creating a script template](/images/jumpserver/v5_admin_wb_tpl_02.png)

## Create a Playbook template

<Steps>

<div>
Open the **Playbook** tab and click **Create**.
</div>

<div>
Enter a name, choose the scope, and upload a ZIP archive of the Playbook.
</div>

<div>
Make sure the archive contains a `main.yml` entry file at its root. Directories
such as `roles/`, `vars/`, and optional files such as `set_env.yml` are allowed
next to it.
</div>

</Steps>

After upload, the Playbook can be selected when creating a Playbook job in
[Jobs](/workbench/job-center/jobs).

## Template parameters

| Parameter | Applies to | Description |
| --- | --- | --- |
| Name | Script, Playbook | Template name |
| Scope | Script, Playbook | Public (everyone) or private (creator only) |
| Module | Script | Script module, such as Shell |
| Content | Script | Script body |
| Variables | Script | Variables and their default values |
| File | Playbook | ZIP archive with `main.yml` at the root |
| Comment | Script, Playbook | Optional description |

## Column reference

| Column | Description |
| --- | --- |
| Name | Template name |
| Module | Script module; Playbook templates show no module |
| Content | Script body preview |
| Comment | Optional note |
| Scope | Public or private visibility |
| Created by | Account that created the template |
| Date created | Creation time |
| Actions | Edit, clone, or delete the template |

<Alert type="tip">
Script templates can be loaded from **Open command** on the
[Adhoc](/workbench/job-center/adhoc) page and from the **Template** field
of a script job. Variables are requested each time the command runs.
</Alert>

<Alert type="warning">
Editing a public template affects every job and Adhoc command that references it.
Check existing usage before changing a shared template, and prefer cloning it into
a private template when you need a variant.
</Alert>
